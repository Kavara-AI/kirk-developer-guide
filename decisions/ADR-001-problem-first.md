# ADR-001: Problem-First Documentation

- **Status:** Accepted
- **Date:** 2026-07-28

## Context

New users need to determine whether Kirk fits their problem before studying engine internals.

## Decision

Documentation will begin with the system, streams, relationships, non-stationarity and operational decision.

## Consequences

Architecture material is secondary to capability fit and benchmarks. This may feel unusual to readers expecting an API-first guide, but it reduces premature implementation.
