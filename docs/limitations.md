# Limitations

This repository should state limitations before presenting performance claims.

## Current documentation limitations

- The benchmark framework is defined before validated Kirk outputs are committed.
- Synthetic data may not capture real microstructure or physical-system complexity.
- Regime labels in synthetic data are generated by construction.
- Output interpretation depends on Kirk's exact API and semantics.
- Comparisons with other methods require careful tuning and fair compute budgets.

## Operational limitations

A system-change signal may not identify:

- root cause
- physical location
- severity
- required intervention
- causal mechanism

## Safety-critical use

Kirk should not replace certified controls, interlocks or human review solely on the basis of an experimental benchmark.

## Required future work

- publish run manifests
- use public real-world datasets
- test robustness to missing and delayed data
- quantify detection delay and false alarms
- document failure cases
- reproduce results across engine versions
