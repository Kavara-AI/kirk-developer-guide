# Benchmark 007 — Inference Cost: Energy and Time per Unit of Signal

**Question this benchmark answers:** for a streaming detection task, how much *time* and
how much *energy* does it cost to produce one unit of output signal — and how does an
explicit energy-based method compare with a general-purpose time-series foundation model?

Most model comparisons report accuracy. This one reports **cost**, on the premise that a
detector you cannot afford to run continuously is not a detector you can deploy. It is
deliberately accuracy-neutral: it measures what each approach costs to produce the same
shaped output, and leaves detection quality to Benchmark 001.

## Why this is not a like-for-like race

The two systems do structurally different amounts of work per unit of output, and any
honest comparison has to state that up front:

- **Kirk** consumes a cross-sectional panel and emits **one scalar per window**. The
  channel count is absorbed into the tensor.
- **A univariate forecaster** (TimesFM and its family) emits **one forecast per channel per
  window**. Reconstructing a single cross-sectional scalar therefore costs N forward passes.

So the per-call column below is context, not a claim. **The defensible unit is
"one minute of output signal"**, and that is what this benchmark standardises on.

## What you need

| | |
|---|---|
| CPU | any x86-64 with RAPL (Intel) or equivalent; results scale, the method does not |
| Python | 3.12+ |
| TimesFM | `pip install timesfm torch --index-url https://download.pytorch.org/whl/cpu` |
| Kirk | a Kirk endpoint — the public MCP surface is sufficient (`kirk_score_book_batch`) |
| Energy | `perf` with `power/energy-pkg/` readable (`perf_event_paranoid <= 0`) |

No proprietary data is required. All inputs are synthetic and generated by
`code/generate_data.py` with a fixed seed.
